# دفتر الحساب — الحزمة الكاملة لـ Cloudflare

## محتويات الحزمة
- `index.html`: واجهة الإدارة العربية، العملاء، سجل الدين والدفعات، وإعداد مفتاح المزامنة وإنشاء/تحديث رابط العميل.
- `worker.js`: API محمي بـ `ADMIN_KEY`، وحفظ بيانات كل عميل في D1، وإنشاء روابط خاصة عشوائية، وإتاحة قراءة الحساب للعميل.
- `portal.html`: صفحة العميل للقراءة فقط، مع سجل العمليات وتفاصيل توزيع الدفعات وتصدير CSV والطباعة/PDF.
- `wrangler.toml`: إعداد Worker وD1 باستخدام Database ID الذي زوّد به المستخدم.
- `migrations/0001_client_accounts.sql`: إنشاء جدول حسابات العملاء والفهرس.
- `schema.sql`: نسخة من SQL لإنشاء الجدول.
- `sw.js`, `manifest.webmanifest`, `icon.svg`: ملفات PWA.

## إعدادات Cloudflare
قاعدة D1 المتوقعة: `business-clients`
Database ID: `3eb1ca79-353f-4c16-9916-0778fe346602`

1. ارفع محتويات الحزمة إلى جذر مستودع GitHub المرتبط بـ Worker `business`. لا ترفع ZIP نفسه بدلاً من الملفات المفكوكة.
2. تأكد أن `index.html`, `portal.html`, `worker.js`, `wrangler.toml` موجودة في جذر المستودع.
3. في D1 افتح قاعدة `business-clients` ثم SQL Console، ونفّذ محتوى `migrations/0001_client_accounts.sql` مرة واحدة. الأمر يستخدم `IF NOT EXISTS` ويمكن إعادة تشغيله بأمان لإنشاء الجدول/الفهرس إذا كانا غير موجودين.
4. في Worker `business` → Settings → Variables and Secrets → Production، أضف Secret اسمه حرفياً `ADMIN_KEY` وقيمة سرية قوية تختارها أنت. لا تحفظ القيمة في GitHub ولا تشاركها مع أي شخص.
5. انشر Worker عبر إعداد Cloudflare المعتاد `npx wrangler deploy`.
6. افتح `https://business.lixgame.workers.dev`، ومن الإعدادات اضغط «إعداد مفتاح المزامنة» وأدخل القيمة نفسها التي وضعتها في Secret.
7. لكل عميل موجود محلياً، اختره واضغط «حفظ بيانات العميل» أو «إنشاء / تحديث رابط العميل» مرة واحدة لمزامنة بياناته الحالية إلى D1 وإنشاء رابطه. عند الحفظ لاحقاً، يحاول التطبيق تحديث بيانات العميل على D1 تلقائياً.

## الحفاظ على البيانات الحالية
- لا تغيّر مفاتيح التخزين المحلية في `index.html`: `debt_book_v1`, `debt_book_clients_v1`, `debt_book_active_client_v1`.
- لا تمسح بيانات المتصفح ولا تستخدم خيار مسح بيانات الموقع. بيانات كانت محفوظة محلياً في جهاز/متصفح الإدارة لا تنتقل تلقائياً إلى D1؛ يجب فتح التطبيق من الجهاز الذي يحتوي البيانات ومزامنة كل عميل.
- خذ نسخة احتياطية من بيانات المتصفح قبل تحديث التطبيق.

## اختبار بعد النشر
1. افتح التطبيق وأدخل ADMIN_KEY من الإعدادات.
2. اختر عميلاً واضغط إنشاء/تحديث رابط العميل؛ يجب أن يظهر الرابط من دون رسالة «غير مصرح».
3. افتح الرابط في متصفح آخر/نافذة خاصة. يجب أن تظهر بيانات هذا العميل فقط.
4. أضف عملية تجريبية أو حدّث وصفاً، احفظ، ثم أعد فتح صفحة العميل وتأكد من التحديث. تجنّب إجراء اختبار يغيّر أرصدة حقيقية إلا إذا كنت مستعداً لحذفه.

## ملاحظات أمان وتشغيل
- لا تضع `ADMIN_KEY` في الملفات أو GitHub. مفتاح الإدارة محفوظ محلياً على جهاز الإدارة فقط.
- روابط العملاء تعتمد على رمز عشوائي طويل؛ يمكن تعطيل رابط من API الإدارة إذا أضيفت واجهة إلغاء لاحقاً.
- هذه الحزمة لا يمكنها نقل بيانات من متصفح لمتصفح دون فتح التطبيق على المتصفح الذي يحتوي البيانات ومزامنتها أول مرة.
- تم فحص بنية ZIP وصياغة JavaScript محلياً، لكن لم يتم إجراء نشر حي داخل حساب Cloudflare الخاص بك أو اختبار شامل باستخدام بياناتك الفعلية.
