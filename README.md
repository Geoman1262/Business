# دفتر الحساب — بوابة العميل (حزمة إعداد وفحص)

## مهم قبل الاستخدام
هذه الحزمة تضيف بوابة قراءة خاصة للعميل عبر رابط ثابت ومزامنة عبر Cloudflare D1. لا ترفع الملفات قبل إكمال الإعداد أدناه. النسخة لا يمكنها مزامنة البيانات القديمة تلقائياً إلا بعد فتح التطبيق وضبط مفتاح الإدارة ثم حفظ ملف كل عميل مرة واحدة.

## الملفات
- `index.html`: واجهة الإدارة الحالية، مع أزرار إنشاء رابط ومزامنة بعد الحفظ.
- `portal.html`: صفحة العميل للعرض وتصدير CSV/Excel والطباعة إلى PDF.
- `worker.js`: API آمن؛ بيانات الإدارة تتطلب `ADMIN_KEY`، والبوابة تقرأ بيانات العميل فقط من خلال رمز عشوائي.
- `migrations/0001_client_accounts.sql`: جدول D1.
- `wrangler.toml`: إعداد Worker وD1. يجب استبدال `REPLACE_WITH_YOUR_D1_DATABASE_ID` بمعرّف قاعدة بياناتك.

## الإعداد المطلوب (مرة واحدة)
1. أنشئ قاعدة D1 باسم `business-clients` من لوحة Cloudflare.
2. انسخ Database ID إلى `wrangler.toml` مكان `REPLACE_WITH_YOUR_D1_DATABASE_ID`.
3. نفّذ `npx wrangler d1 migrations apply business-clients --remote` أو نفّذ SQL الموجود في `migrations/0001_client_accounts.sql` من محرر D1.
4. اضبط سر Worker: `npx wrangler secret put ADMIN_KEY` وأدخل قيمة قوية. لا تضع السر داخل الملفات أو GitHub.
5. انشر الملفات مع إعدادات Worker. احتفظ بنسخة احتياطية من بيانات المتصفح قبل ذلك.
6. افتح تطبيق الإدارة، اذهب إلى الإعدادات > إعداد مفتاح المزامنة، وأدخل نفس قيمة `ADMIN_KEY` على جهاز الإدارة فقط.
7. افتح ملف كل عميل واضغط «حفظ بيانات العميل» أو «إنشاء / تحديث رابط العميل» مرة واحدة لمزامنة البيانات وإنشاء الرابط. بعد ذلك، كل حفظ للعميل على جهاز الإدارة يرسل أحدث بياناته إلى D1.

## الفحوصات التي أُجريت
- فحص بناء ZIP وسلامة أرشيفه.
- فحص صياغة JavaScript في صفحات HTML و`worker.js` باستخدام Node.js.
- فحص وجود endpoints للبوابة ومزامنة العميل.

## حدود يجب معرفتها
- لم يتم النشر إلى حساب Cloudflare الخاص بك أو اختبار D1 الحقيقية من هذه الحزمة.
- عند أول ربط، افتح كل ملف عميل واضغط حفظ/إنشاء رابط حتى تُرفع بياناته المحلية إلى قاعدة البيانات.
- صفحة العميل للقراءة فقط؛ لا تتيح تعديل أو تسجيل دفعات.
- الرابط بمثابة سر وصول؛ أرسله للعميل المعني فقط. يمكن إلغاء الرابط من لوحة D1 بتغيير `active=0` للعميل، أو نضيف زر إلغاء من التطبيق في تحديث لاحق.
- البيانات المالية حساسة؛ استخدم مفتاحاً قوياً، لا تشارك `ADMIN_KEY`، وخذ نسخة احتياطية قبل النشر.
